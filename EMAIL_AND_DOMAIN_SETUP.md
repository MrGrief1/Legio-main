# Почта (Resend) и переезд домена legio.news

> **Статус на 18 августа 2026.** Шаги 2 и 3 (домен в Resend + DNS в Timeweb) выполнены:
> `legio.news` подтверждён в аккаунте Resend `maksurazov1502`, регион us-east-1, статус **Verified**.
> В Timeweb добавлены `TXT @ resend-domain-verification=…`, `TXT resend._domainkey` (DKIM),
> `TXT send v=spf1 include:amazonses.com ~all`, `MX send → feedback-smtp.us-east-1.amazonses.com (10)`.
> A-запись, MX и SPF корня не тронуты — старый сайт и почта на нём работают.
> **Осталось:** создать API-ключ в Resend и задать `RESEND_API_KEY` + `RESEND_FROM` в Railway (§4),
> затем проверка (§5) и переезд домена (§6).

Порядок здесь важен: **сначала почта, потом домен**. Записи, которые нужны Resend (TXT, DKIM и MX
на поддомене `send`), не трогают A/CNAME, по которым сейчас открывается старый сайт, — их можно
добавить прямо сегодня, и старый сайт продолжит работать. Переключение самого домена на новый
проект — последний шаг, когда рассылка уже проверена.

## 1. Что появилось в коде

Одноразовые коды на почту для всех чувствительных действий:

| Сценарий | Маршруты |
|---|---|
| Регистрация | `POST /api/auth/register` → `/api/auth/register/verify` (+ `/register/resend`) |
| Вход (второй фактор) | `POST /api/auth/login` → `/api/auth/login/verify` (+ `/login/resend`) |
| Забыли пароль | `POST /api/auth/forgot-password` → `/api/auth/reset-password` |
| Смена пароля | `POST /api/user/security/password/request` → `/password/confirm` |
| Смена / привязка почты | `POST /api/user/email/request-current` → `/verify-current` → `/request-new` → `/confirm` |
| Включить / отключить вход по коду | `POST /api/user/security/mfa/request` → `/mfa/confirm` |
| Состояние защиты аккаунта | `GET /api/user/security/status` |

Файлы: [`server/mailer.js`](server/mailer.js) — отправка через Resend и шаблон письма,
[`server/emailAuth.js`](server/emailAuth.js) — выдача и проверка кодов,
[`designe/components/SecuritySettings.tsx`](designe/components/SecuritySettings.tsx) — вкладка
«Безопасность».

Правила, заложенные в коде: код 6 цифр, живёт 10 минут (регистрация — 15), 5 попыток ввода,
пауза 60 секунд между отправками, в базе хранится только SHA-256 кода, письмо уходит **до** записи
кода в базу (неудачная отправка не гасит действующий код).

**Вход по коду — доброволен.** Причина не в удобстве: у аккаунтов, перенесённых из WordPress, в
поле логина лежит ник, а не адрес, и код им отправлять некуда. Такой аккаунт видит в настройках
«Почта не привязана» и может привязать её, подтвердив текущим паролем; после этого доступны и
второй фактор, и восстановление пароля.

## 2. Resend: подтверждение домена

1. Панель Resend → **Domains** → **Add Domain** → `legio.news`.
   Регион (`eu-west-1` / `us-east-1`) влияет на MX-запись — выберите ближе к аудитории и запомните.
2. Resend покажет 3–4 записи. Их формы (значения берите **из панели**, не отсюда):

   | Тип | Имя | Значение | Прим. |
   |---|---|---|---|
   | MX | `send` | `feedback-smtp.<регион>.amazonses.com` | приоритет 10 |
   | TXT | `send` | `v=spf1 include:amazonses.com ~all` | SPF для поддомена |
   | TXT | `resend._domainkey` | `p=MIGfMA0GCSq...` (длинный ключ) | DKIM |
   | TXT | `_dmarc` | `v=DMARC1; p=none;` | необязательно, но желательно |

3. Все записи — на **поддоменах** (`send`, `resend._domainkey`, `_dmarc`). Корневые A/CNAME и MX
   корня не затрагиваются, почта и сайт на старом хостинге работают как работали.
4. **Create API Key** → права `Sending access` → скопируйте ключ (`re_...`), он показывается один раз.

## 3. Timeweb: добавить записи

Панель Timeweb → домен `legio.news` → **DNS-записи** → добавить всё из таблицы выше.

Осторожно с двумя вещами:

* Timeweb в поле «Имя» ожидает **только поддомен** (`send`, а не `send.legio.news`). Если
  подставить полное имя, запись станет `send.legio.news.legio.news`.
* DKIM-значение длинное — вставляйте целиком, без переносов и пробелов.

Затем в Resend нажмите **Verify**. Обычно 5–30 минут; статус должен стать `Verified`.

## 4. Railway: переменные

В сервисе `chat` → **Variables**:

```bash
RESEND_API_KEY=re_...                      # ключ из Resend
RESEND_FROM=Legio <noreply@legio.news>     # домен обязан быть Verified в Resend
```

До подтверждения домена можно проверить отправку на свой адрес:
`RESEND_FROM=Legio <onboarding@resend.dev>` — Resend разрешает этот адрес без верификации, но
письма уйдут только на почту владельца аккаунта Resend.

Необязательные:

```bash
EMAIL_CODE_RATE_LIMIT_MAX=20   # запросов кода с одного IP в час (по умолчанию 20)
ALLOW_UNSENT_CODES=true        # ТОЛЬКО для отладки: печатать коды в лог, если ключа нет
```

`ALLOW_UNSENT_CODES` в production не включайте — коды окажутся в логах Railway.

## 5. Проверка (ещё на railway-адресе, до переезда домена)

На `https://<сервис>.up.railway.app`:

1. Зарегистрируйте новый аккаунт → письмо с кодом должно прийти за секунды.
2. Настройки → Безопасность → включите «Вход по коду с почты» → выйдите и войдите заново.
3. Смените пароль и почту — оба сценария требуют код.
4. «Забыли пароль?» на форме входа.

Если письма не приходят — Railway → Logs. `[mailer] Resend вернул ошибку: 403` почти всегда значит,
что домен в `RESEND_FROM` ещё не Verified.

## 6. Переезд домена на новый сайт

Делайте это **после** пункта 5 — рассылка уже должна работать.

1. **Снизьте TTL заранее.** В Timeweb у текущих записей `@` и `www` поставьте TTL 300 секунд и
   подождите старый TTL (обычно час). Тогда откат займёт минуты, а не сутки.
2. **Railway** → сервис `chat` → **Settings** → **Networking** → **Custom Domain** → `legio.news`,
   затем отдельно `www.legio.news`. Railway выдаст целевые значения:
   * для `www` — CNAME на `<...>.up.railway.app`;
   * для корня `@` — либо ALIAS/ANAME, либо A-запись с IP, который покажет Railway (у корня CNAME
     по стандарту невозможен).
3. **Timeweb** → замените существующие `@` и `www` на значения из Railway. Старые A-записи на
   хостинг WordPress удалите — иначе часть посетителей попадёт на старый сайт.
4. Дождитесь, пока в Railway у домена появится галочка и выпустится TLS-сертификат (обычно
   несколько минут, иногда до часа).
5. Проверьте: `https://legio.news`, `https://www.legio.news`, вход и регистрация, письма.

**Что НЕ трогать при переезде:** записи `send`, `resend._domainkey`, `_dmarc` и MX корня. Первые три
держат рассылку, MX корня — вашу обычную почту на домене.

**Откат:** вернуть прежние `@` и `www` в Timeweb. При TTL 300 старый сайт вернётся за несколько
минут. Домен в Railway можно оставить — без DNS он просто не используется.

### Обязательно: отключить синхронизацию с WordPress

После переезда уберите из переменных Railway `WP_SYNC_ON_STARTUP` (и заодно `WP_DB_*`, если они
больше не нужны).

Причина конкретная. При `WP_SYNC_ON_STARTUP=true` сервер на каждом запуске переносит пользователей
из базы WordPress запросом `ON CONFLICT(id) DO UPDATE SET ... password = excluded.password`
([`server/wordpress_sync.js`](server/wordpress_sync.js)). То есть **любой перезапуск возвращает
перенесённым пользователям их старые пароли** — включая тех, кто только что сменил пароль через код
с почты. Привязанная почта, подтверждение и вход по коду при этом сохраняются: этих колонок в
переносе нет. Пока миграция шла, поведение было правильным; после переезда оно ломает ровно тот
сценарий, ради которого всё делалось.

Разовую синхронизацию при необходимости всегда можно запустить вручную:
`POST /api/admin/sync/wordpress` из-под администратора.

## 7. Локальная разработка

Без `RESEND_API_KEY` сервер не падает: письма не отправляются, а коды печатаются в лог сервера —
`[emailAuth] Код для user@example.com (register): 123456`. Это работает только при
`NODE_ENV != production`.

```bash
cd server && SECRET_KEY=любой-длинный-ключ npm run dev
```
